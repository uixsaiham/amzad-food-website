# Amzad Food Website — Project Scope & Quotation

**Prepared for:** Amzad Food  
**Prepared on:** 24 October 2026  
**Proposed project fee:** USD $200 — negotiable  
**Service:** Figma design system, website UI design, frontend implementation and developer handoff  
**Status:** Proposed scope for client review

## 1. Project overview

The Amzad Food project covers the customer-facing website from its design foundations in Figma through UI design and frontend implementation using Next.js, React and TypeScript. The scope includes a project-specific design system, the agreed storefront screens, responsive frontend interactions and a documented handoff to the client's backend developer.

The proposed total fee is $200 and is open to negotiation. It covers the design-to-frontend scope described below. The final amount will be agreed before acceptance. Live ecommerce services require separate backend development and integration.

## 2. Figma design system and UI design

- Project color palette, typography hierarchy, spacing, corner-radius and shadow styles.
- Reusable components for buttons, form fields, product cards, badges and shared navigation, with relevant interaction states.
- Organization of styles and components within the project Figma file for consistent use across the agreed screens.
- Customer-facing UI designs for the screens listed below, including desktop and mobile layouts.
- Implementation of the agreed designs in the frontend, with layout adjustments for tablet widths.
- Editable Figma file access or an agreed transferable copy, including the project design system and screen designs.

This is a design system for the Amzad Food storefront. A separate enterprise component library, additional brands/themes and admin dashboard designs are outside this scope.

## 3. Included screens and features

| Area | Included deliverable |
| --- | --- |
| Homepage | Existing hero, category navigation, product sections, brand/story sections and footer |
| Product catalog | Existing product grid, local search, category filters and pagination |
| Product details | Product images/gallery, catalog pack and price, information tabs and related products |
| Quick View | Product preview, quantity selection, add-to-cart and checkout navigation |
| Shopping cart | Add/remove products, adjust quantities and display estimated totals using frontend data |
| Checkout | Customer/address form, frontend validation, existing promotional calculations, COD presentation and clearly identified local order preview |
| My Orders | Existing order-list design, status filters, empty state and device-saved preview records |
| Order tracking | Lookup interface, order-detail layout, status timeline and existing HTML invoice presentation using local/sample data |
| Blogs | Existing blog listing and article layouts |
| FAQ | Existing FAQ page and interactions |
| Shared interface | Header, footer, mobile menu, account-form layout, wishlist interface and scripted support widget |

The agreed Figma screens and corresponding project screenshots define the visual baseline for frontend delivery. Product and article detail pages reuse templates; the fee does not include a separately designed page for every item.

## 4. Frontend implementation and verification

- Responsive implementation of the agreed layouts for mobile, tablet and desktop.
- Correction of reproducible frontend defects within the included screens.
- Checks of navigation, images, cart actions and form validation in a current Chrome desktop browser and a mobile viewport before final acceptance.
- TypeScript checking and a successful production build.
- Check of local links and asset targets in the exported website.

These checks cover the supplied frontend. Server behavior, payment processing, account security and real order fulfillment are outside this scope.

## 5. Functional boundaries

| Feature | What this delivery provides | What requires separate work |
| --- | --- | --- |
| Products | Display from existing local catalog data | Product database, admin editing, live inventory and backend-issued IDs |
| Cart | Browser-based cart interactions | Account synchronization and server stock validation |
| Checkout | Form, estimated totals and device-only preview | Persistent real orders, authoritative pricing and order notifications |
| Customer accounts | Account interface with unavailable services clearly identified | Real login, registration, sessions, OTP and password recovery |
| Orders and tracking | Existing layouts and labeled preview behavior | Customer-authorized API access, live statuses and courier updates |
| Reviews and wishlist | Existing frontend/local interactions | Shared persistence, moderation and cross-device synchronization |
| Newsletter and chat | Offer-preview interface and scripted support | Subscription service, messaging platform or live support backend |

Local browser storage and sample records are demonstration mechanisms. They do not constitute a production order system. API connection work is not included in this $200 quotation.

## 6. Revisions and support

**One consolidated revision round across the design and frontend scope** is included. The client supplies one combined list of minor changes to text, colors, spacing or replacement images within the agreed layouts. Approved design changes will be reflected in the corresponding frontend screens.

New pages, new features, changed user flows and major layout redesigns require a separate estimate. Corrections to reproducible defects within the agreed scope do not consume the revision round.

**Seven calendar days of handoff support** begin when the final deliverables are handed over. This covers setup questions, explanations of the existing code and clarification of integration points. It excludes implementing APIs, building additional features and ongoing maintenance.

## 7. Deliverables

1. Editable Figma design file or agreed copy containing the project design system, reusable components and agreed desktop/mobile screen designs.
2. Frontend source code in the agreed repository or source archive.
3. README with installation, local execution and build instructions.
4. Backend handoff notes identifying data flows and integration points.
5. Proposed API contract for discussion with the backend developer; it is not an implemented API.
6. Frontend audit record with completed checks and outstanding dependencies.

Admin dashboard design and implementation are excluded unless separately agreed in writing.

## 8. Client responsibilities

The client supplies and approves final product names, pack sizes, prices, images, descriptions, contact information and business policies. Existing placeholder or sample content must be approved, replaced or excluded before a live launch.

The client assigns a backend developer for real ecommerce functionality and provides any access required for the agreed source-code handoff. The client consolidates feedback into the included revision round.

## 9. Exclusions

- Backend services, API integration, database setup and data migrations.
- Admin dashboard design, frontend or backend implementation.
- Real authentication, OTP, password recovery and social sign-in.
- Live order processing, inventory management, courier integration and payment gateways.
- SMS, email, newsletter platforms and live-chat services.
- Domain registration, hosting, production deployment, server configuration and ongoing monitoring or maintenance.
- Third-party subscriptions, service charges and transaction fees.
- New branding, original photography, copywriting, translation or bulk product/article entry.
- Additional screens, major redesigns and functionality introduced after scope approval.

## 11. Acceptance and scope changes

Delivery is accepted when the Figma design system and agreed screen designs are supplied, the frontend reflects the visual baseline, included interactions pass the stated checks, the production build succeeds and handoff documentation is provided. Outstanding backend dependencies are recorded separately and do not represent included live functionality.

Any request beyond this scope must be described and priced before additional work begins. Changes to price or delivery dates require agreement from both parties.
